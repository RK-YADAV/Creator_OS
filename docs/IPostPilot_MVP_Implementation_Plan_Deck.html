Build the smallest system that can prove the workflow.

An implementation plan for a real, rendered-video MVP that uses one Python application, filesystem artifacts, an RTX PRO 6000 GPU, FFmpeg, and selective AI API access—without a database or complex infrastructure.

GPU-firstWeb reviewJSON artifactsHuman approval
Core decision: omit infrastructure complexity, not experimental discipline. The MVP must still preserve timestamps, render real clips, persist decisions, and measure workflow improvement.
01 / Executive summary

What this MVP is designed to prove

Hypothesis: Given a long-form video, creator examples, and human review, I-PostPilot can help a creator reach acceptable YouTube Shorts and Instagram Reels faster than their manual workflow.

Inputs

  • Long-form MP4.
  • Optional transcript.
  • Creator onboarding answers and archive examples.
  • Platform and language settings.

Outputs

  • Versioned creator skill profile for approval.
  • Candidate windows.
  • Rendered 9:16 MP4 previews.
  • Captions, titles, evidence, and decisions.

Success measures

  • Time to first publishable clip.
  • Time to five clips.
  • Approval and major-edit rates.
  • Timestamp correction rate.

What is deliberately excluded

Multi-tenant production infrastructure, autonomous publishing, fine-tuning, complex billing, and database-backed scale. These are roadmap items, not prerequisites for the experiment.

03 / Working mechanism

Flow 1 — Media-to-evidence pipeline

Flow 1 transforms the source video into a reusable evidence timeline. Each stage writes an artifact so later stages can be rerun without repeating expensive GPU work.

01 / INTAKEValidate input

File, codec, audio, duration, transcript, disk.

02 / MEDIANormalize

WAV (working audio), proxy MP4 (lighter video), metadata, fingerprint.

03 / SPEECHTranscribe

ASR converts speech to text with word timestamps, language, speakers, and confidence.

04 / AUDIOAnalyze sound

VAD (voice activity detection), pauses, energy, speech rate, events.

05 / VIDEOAnalyze frames

Shots, keyframes, OCR, framing, crop safety.

06 / CREATORBuild skill profile

Analyze examples, generate profile, creator edits and approves.

07 / CACHERegister artifacts

Manifest, versions, profile status, warnings.

OUTPUTEvidence timeline

Reusable JSON artifacts plus approved creator profile for Flow 2.

08 / FAQ

Media-processing terms in plain language

These components do different jobs. Some understand the content, while others only inspect or transform media files.

WAV

Working audio file. The system extracts the audio track from the MP4 into a consistent format so speech and sound models can process it reliably.

It is an internal artifact, not the final creator output.

Proxy MP4

Smaller working video. A lower-resolution copy used for faster frame analysis, previews, and scene detection. The original remains untouched for final rendering.

ASR

Automatic Speech Recognition. Converts spoken audio into timestamped text. Faster-Whisper is the recommended ASR model for English, Hindi, and Hinglish.

VAD / Silero VAD

Voice Activity Detection. Finds where speech and silence occur. Silero VAD is the lightweight model used to improve boundaries and avoid dead air.

pyannote diarization

Speaker identification over time. Labels turns such as Speaker 1 and Speaker 2, helping avoid awkward cuts between a host and guest.

Optional for the first MVP because it costs more compute and needs model setup.

FFmpeg / ffprobe

Media tools. FFmpeg extracts, converts, cuts, resizes, captions, and renders video. ffprobe inspects duration, codecs, resolution, frame rate, and streams before processing.

PySceneDetect

Visual shot-change detector. Finds points where the camera, slide, or visual composition changes so clip boundaries and thumbnails can align with natural transitions.

Simple mental model: ffprobe asks “what is this file?”, FFmpeg changes the file, ASR says “what was said?”, VAD says “when was someone speaking?”, pyannote says “who was speaking?”, and PySceneDetect says “when did the picture change?”
09 / Component classification

Deterministic, probabilistic, human-in-the-loop

deterministic probabilistic human

Deterministic

  • File validation.
  • FFmpeg extraction/rendering.
  • Timestamp arithmetic.
  • Boundary snapping.
  • JSON/schema checks.
  • Run state and manifests.
  • Export packaging.

Probabilistic

  • ASR and diarization.
  • Embeddings and similarity.
  • Audio/visual interpretation.
  • Narrative ranking.
  • LLM reranking.
  • Titles, hooks, captions.
  • Translation.

Human authority

  • Creator profile correction.
  • Candidate approval.
  • Boundary edits.
  • Caption/title edits.
  • Rejection reasons.
  • Publishability judgment.
  • Evaluation labels.
Safety principle: probabilistic components propose meaning; deterministic components protect evidence and file correctness; the human decides whether the result is worth publishing.

12 / Implementation sequence

Build order and exit criteria

  1. Environment: JarvisLabs CUDA, FFmpeg, model cache, persistent directories. Smoke test
  2. Evidence: one complete video, transcript, word timestamps, proxy, reusable artifacts. Traceable
  3. Candidates: 30/45/60-second windows with aligned boundaries. Timestamp-correct
  4. Rendering: real 9:16 previews with captions and manifest. Reviewable
  5. Web review: approve/edit/reject and time tracking. Measurable
  6. Evaluation: manual, rules, embeddings, hybrid comparisons. Evidence-led
  7. Cohort: repeat with multiple creators before personalization claims. Generalizable
Go/no-go: do not add fine-tuning or auto-publishing until the system can repeatedly render timestamp-correct clips, preserve Hindi/Hinglish meaning, capture corrections, and reduce review time against a manual baseline.
13 / Conclusion

Simple infrastructure. Serious experiment.

A database-free MVP is technically sufficient because the hypothesis concerns creator workflow value—not production scale.

Build now

One Python app, one GPU worker, FFmpeg, JSON artifacts, web review, rendered clips, one LLM/API.

Protect

Word-level evidence, artifact reuse, real/mock labeling, deterministic validation, creator authority.

Measure

Time-to-publish, approval, edits, boundary corrections, candidate recall, creator reuse intent.

Final recommendation: use the RTX PRO 6000 and JarvisLabs credits to build an evaluation-ready, file-based media workflow first. Add databases and production infrastructure only after the creator workflow shows repeatable value.

The MVP succeeds when it helps a creator make a confident publishing decision faster—not when it produces the most elaborate architecture.

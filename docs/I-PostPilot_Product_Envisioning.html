I-PostPilot

An AI-assisted content repurposing workspace that learns a creator's style from their work artifacts, converts long-form video into short-form clips, and keeps the creator in control of every publishable output.

deterministic controlsprobabilistic intelligencehuman approval required

deterministic controls

Key decisions: validate uploads, enforce workspace ownership, lock state transitions, retry only safe failures, and refuse outputs that lack evidence or valid media constraints.

probabilistic intelligence

Key decisions: propose themes, clip candidates, hooks, captions, and style signals from transcript and archive evidence while keeping confidence and uncertainty visible.

human approval required

Key decisions: accept, reject, or edit any publishable clip, confirm final captions, and authorize any external publish flow before work leaves the workspace.

1. Product promise and MVP boundary

Promise: I-PostPilot turns a creator's existing MP4 content and work archive into evidence-backed short clips without replacing the creator's editorial judgment.

The MVP supports one creator, one workspace, MP4 input, and one short-video output format. The first release should not attempt autonomous publishing, full video understanding, or a general-purpose social media scheduler.

Flow 1: Creator setup

Collect persona preferences and 15-20 work artifacts. Analyze them asynchronously and produce a versioned CREATOR_SKILLS.md profile.

Flow 2: Clip production

Upload an input video, find strong segments, generate an editorial preview, and allow the creator to refine the result through an AI editor chat.

Non-negotiable

The model may recommend, draft, and explain. The creator approves the final clip and its caption before publication.

5. Flow 1 - creator onboarding and skill profile

The objective is to transform explicit preferences and real work artifacts into a creator-controlled, versioned instruction profile. The profile is an aid to generation, not an irreversible persona label.

  1. Create workspace: UI calls POST /v1/workspaces. Auth service verifies the user and creates a workspace.
  2. Save declared preferences: UI calls PUT /v1/creators/{creatorId}/preferences with delivery style, visual preferences, editing rules, and hook preferences.
  3. Upload artifacts: Asset Service returns signed URLs from POST /v1/assets/upload-intents. Browser uploads MP4, image, reel, or RAW files directly to object storage.
  4. Finalize each upload: UI calls POST /v1/assets/{assetId}/complete. Asset Service verifies checksum, type, and ownership, then emits artifact.ready.
  5. Create onboarding job: UI calls POST /v1/creator-profiles/{creatorId}/build. API immediately returns job_id.
  6. Inspect media: Orchestrator calls Media Service for metadata, audio extraction, thumbnails, and a normalized representation.
  7. Transcribe audio artifacts: Orchestrator calls Transcription Service for audio-bearing files. Images and silent assets are passed to visual metadata extraction or marked as non-transcript artifacts.
  8. Index the archive: Archive Service stores searchable text, metadata, embeddings, and links each observation to its source artifact.
  9. Analyze the creator: Creator Intelligence Service receives preferences plus a bounded sample of archive observations. The model returns structured tone, topics, hook patterns, editing preferences, visual patterns, and explicit evidence references.
  10. Validate and version: Application code validates the schema, rejects unsupported claims, creates creator_skills_v1, and stores the raw model response for auditability.
  11. Present for approval: UI receives job.completed, fetches GET /v1/creator-profiles/{creatorId}/skills, and displays a pre-filled editable profile.
  12. Learn only after confirmation: Creator edits are saved as explicit preferences. They are not silently merged into the profile.

6. Flow 2 - video to short clip

The objective is to make clip creation a reviewable editorial workflow. The AI proposes a clip plan; the rendering system executes only validated time ranges and the creator approves the preview.

  1. Upload source MP4: Asset Service validates the upload and returns asset_id.
  2. Create clip job: UI calls POST /v1/clip-jobs with source asset, target aspect ratio, duration range, caption preferences, and creator_skills_version.
  3. Prepare media: Orchestrator calls Media Service for duration, frame rate, audio track, proxy video, thumbnails, and normalized audio.
  4. Transcribe: Transcription Service produces timestamped words, sentences, speakers, and confidence values.
  5. Retrieve creator context: Archive Service retrieves similar accepted clips/posts and Creator Intelligence Service returns the active skill profile.
  6. Find candidate moments: Clip Intelligence Service receives transcript, timestamps, skills, and archive context. It returns several candidates with hook, start/end time, rationale, confidence, and evidence.
  7. Apply deterministic validation: Orchestrator rejects invalid ranges, clips beyond source duration, clips outside the configured duration, and candidates with missing transcript evidence.
  8. Render preview: Render Service receives one selected or top-ranked valid plan and creates a low-resolution preview with captions.
  9. Run review checks: Review Service checks transcript support, caption timing, style fit, archive repetition, and output constraints. Uncertainty is displayed as a warning.
  10. Show editorial preview: UI displays video preview, timeline, transcript, evidence, warnings, and the editor chat.
  11. Interpret chat commands: Editor Chat Service converts messages such as "start later and remove the first sentence" into a typed edit plan. It cannot execute arbitrary shell or media commands.
  12. Re-render: If the plan passes validation, Render Service creates a new preview version. The old version remains available for comparison.
  13. Approve: Creator calls POST /v1/clip-jobs/{id}/decisions with accepted, edited, or rejected. Only accepted output can reach a future publishing integration.

7. AI model placement

TaskModel capabilityPlacement and reason
MP4 transcriptionSpeech-to-text with timestamps and diarizationTranscription provider or Whisper-class model. This is separate from the text LLM because timestamp accuracy is the primary concern.
Archive embeddingsSemantic vector representationEmbedding model at ingestion time; retrieve top candidates before calling a reasoning model.
Profile extractionStructured analysis of examplesFast structured-output LLM. It must return evidence IDs and confidence rather than unsupported personality claims.
Clip candidate rankingLong-context reasoning and editorial judgmentStronger LLM after deterministic segmentation and retrieval. It proposes, never publishes.
Chat command parsingIntent extraction into a small command schemaFast LLM constrained to commands such as trim, change captions, crop, reorder, and regenerate.
Quality evaluationClaim comparison, voice and novelty estimationSmaller verifier model plus deterministic checks. Results are warnings and evidence, not absolute truth.

Use a model router so extraction, classification, and formatting use a fast model, while ambiguous editorial ranking and final draft/profile synthesis use a stronger model. Keep model names configurable in environment settings rather than hard-coding them into service logic.

8. Workflow state and asynchronous execution

Video processing and model calls can take seconds or minutes. Do not keep the browser request open. Each long-running operation is a job with durable state and progress events.

ONBOARDING:
created -> uploading -> indexing -> analyzing -> awaiting_creator_review -> active | failed

CLIP_JOB:
created -> validating -> transcribing -> finding_candidates -> rendering_preview
          -> checking -> review_ready -> editing -> rendering_preview
          -> approved | rejected | failed

Workers consume queue messages such as artifact.ready, transcript.ready, profile.build.requested, and render.requested. The orchestrator records an idempotency key for every message so retries do not duplicate renders, charges, or database records.

9. Failure and quality rules

FailureRequired behavior
Corrupt, non-MP4, or oversized uploadReject before AI processing and show a repairable validation message.
No audio track or transcription failureStop the dependent workflow; preserve the asset and offer an explicit retry.
Low-confidence words in a proposed hookShow the timestamp as unverified and ask the creator to confirm or choose another candidate.
Invalid model JSONRetry once with schema errors; then mark the step failed. Never parse by silently guessing fields.
Render failureKeep the clip plan and create a retryable render job; do not mark the preview ready.
Creator rejects outputStore the rejection and reason. Do not silently regenerate or erase the rejected version.
AI provider timeoutRetry bounded transient failures with backoff; surface a clear job error when limits are reached.

10. Implementation order

  1. Build authentication, workspace isolation, asset uploads, object storage, and job tracking.
  2. Build MP4 metadata validation, audio extraction, timestamped transcription, and transcript review.
  3. Build artifact indexing, embeddings, archive retrieval, and creator profile versioning.
  4. Build deterministic clip plans and a basic renderer before adding AI ranking.
  5. Add AI candidate selection with evidence, confidence, and bounded structured output.
  6. Add captions, preview checks, and the editor chat as typed editing commands.
  7. Add creator approval, feedback persistence, metrics, and a failure demonstration.
  8. Only after the loop is stable, add optional publishing integrations or visual AI features.

11. Hackathon demo success criteria

Traceability

Click a claim or caption and jump to the exact transcript timestamp in the source video.

Agency

Show the creator changing a clip through chat, reviewing the result, and approving it explicitly.

Learning

Show a rejected or edited result becoming a recorded preference for a later run.

Reliability

Demonstrate an unsupported or low-confidence moment being surfaced rather than silently shipped.

I-PostPilot design principle: deterministic services protect state, evidence, permissions, and media integrity; probabilistic services propose meaning and style; the creator controls the final editorial decision.
